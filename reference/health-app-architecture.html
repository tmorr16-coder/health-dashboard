Architecture Document · v1

Health Dashboard Backend

Pragmatic system design for a multi-source health tracking application

Executive Summary

This is a "buy where it's commodity, build where it's differentiated" architecture. The integrations layer (the hardest part) is offloaded to a health data aggregator. The custom work focuses on what makes the app yours: the workout tracker, Zepbound dose logic, AI insights, and the UX. Total time to MVP: ~2–3 weekends of focused work if you have a developer. Monthly cost at single-user scale: under $30.

Data Layer
Postgres on Supabase
Supabase · TimescaleDB extension
One database for everything. Relational tables for users, workouts, doses, settings. TimescaleDB extension turns the same DB into a time-series store for HRV, weight, blood pressure trends — no separate metrics database needed.

Key Decisions & Risks

✓ Smart Choices
  • Aggregator over direct integration: Saves 60–80% of integration time. The "build it yourself" temptation is a trap unless you're at scale.
  • Postgres over NoSQL: Health data is highly relational. TimescaleDB handles the time-series workload without a second database.
  • Next.js over split frontend/backend: One repo, one deploy, shared types. Splitting is premature optimization.
  • Server-side AI calls: Never put the Claude API key in the client. Proxy through your API.
⚠ Risks to Watch
  • HIPAA compliance: If sharing with providers, you'll need a BAA with vendors. Most consumer-grade services don't sign them. Consider AWS HIPAA-eligible services if going this route.
  • Aggregator lock-in: Terra/Vital go down → your app goes down. Consider building direct fallbacks for Withings and Oura since those are easy.
  • Token refresh: OAuth tokens expire. Build retry/refresh logic into the webhook handlers from day 1.
  • Data privacy: Encrypt PHI at rest. Use row-level security in Supabase. Document a deletion flow for GDPR/CCPA.
  • Apple Health quirks: Even with an aggregator, Apple Health data lags by minutes-to-hours and can have gaps. Plan UX for stale data.

Recommended First Step

Start with a 1-day spike

Before committing, do this: spin up a free Supabase project, sign up for Terra's free tier, and connect your own Oura ring. See real data flowing into your database within an afternoon. That single working integration tells you 80% of what you need to know about the rest of the build.
